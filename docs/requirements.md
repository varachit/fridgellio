# Fridgellio product requirements

## Goals and scope

- Track pantry items and groceries by quantity and storage location in one shared pantry per household. Each member signs in with their own account.
- Add pantry items and groceries manually, from a photo analyzed by OpenAI, or by looking up a barcode with OpenAI web search or Open Food Facts.
- Surface groceries with approaching recorded expiry dates.
- Let each member manage their own **Foods to avoid** in **Settings**. Use that list to filter the shared pantry when they request a menu.
- Preview a pantry-only request for up to five meal ideas. AI recipe generation, bilingual cooking steps, and saving generated menus are deferred in V1.
- Support English and Thai in the app. Generate and save both languages for AI-generated grocery names and menus.

Household supplies, a recipe catalog, recipe ranking, deductions from a generated menu, notifications outside the app, receipt import, and automatic shopping lists are outside first-release scope.

## Functional requirements

| ID | Requirement |
| --- | --- |
| AUTH-01 | Let each member register and sign in with a case-insensitive username and a password of 8 to 128 characters. Require a first name and last name at registration. Trim surrounding whitespace and accept 1 to 200 characters per name. NextAuth handles web sign-in with the FastAPI account service, which stores hashed passwords. Use expiring server-side sessions and revoke the current session on sign-out. Limit repeated login attempts. Older accounts without a saved name use their username as their display name. Profile picture uploads are disabled. |
| HH-01 | Give signed-in members of the same household access to the same inventory across all storage locations, inventory history, and cooking equipment. Verify household membership before every read or write of shared data. Keep open entry details in sync with the inventory list, which refreshes every 30 seconds while the tab is visible and when the member returns to it. |
| HH-02 | In **Household**, list the people in the signed-in member's household and identify the household owner. Show each person's name and profile picture if available. Use their username when names are empty and initials when a picture is unavailable. |
| HH-03 | In **Household**, let the owner create single-use invitation codes such as `K7RM-3X9D`, view pending invites and their expiry times, and remove any pending invite. Generate codes with uppercase letters and digits, excluding `I`, `O`, `0`, and `1`. Show each code when created. Accept lowercase letters and an omitted hyphen when joining. Previously issued codes remain valid until used, removed, or expired. Codes expire after 24 hours, and removing an invite invalidates its code immediately. Limit invite management to the household owner. Allow 10 join attempts per account in each 15-minute window. |
| INV-01 | Add, edit, and remove stock entries for pantry items and groceries. An entry needs an item name, positive quantity, unit, and storage location. Its expiry date is optional. Offer pantry, fridge, freezer, and other as location choices. |
| INV-02 | Keep quantities from separate purchases as separate entries so dates and locations remain accurate. Allow searching by item name and filtering by location. |
| INV-03 | Record use or discard against a specific entry. Show the quantity remaining and prevent deductions above the available amount. Hide zero-quantity entries from active inventory and retain usage and discard records. Use removal to correct erroneous entries. |
| INV-04 | Let the user take a grocery photo and send it to OpenAI for analysis. Return one or more editable item suggestions with English and Thai names. Suggest a quantity and unit or an expiry date when clearly visible, and leave uncertain fields blank. Let the user retake the photo or switch to manual entry if the photo cannot be read or the request fails. |
| INV-05 | When the user selects **Scan barcode**, open the camera and send one frame at a time to the backend decoder until it reads a barcode or the user stops scanning. Stop the camera after a successful read and look up the returned digits automatically, preserving leading zeros. Allow users to type or edit the digits and select **Look up product**. For lookup, use a verified correction when the barcode matches exactly. Otherwise, search for an exact match with OpenAI web search when configured. If no sourced match has both a name and a brand, use the Open Food Facts v3 product endpoint with country `th` and the current app language. Return the barcode, name, and brand, plus optional localized names and numeric package quantity and unit. Display the source link for web results. Prefill the editable quantity and unit when the package measurement fits the inventory form, and ask the user to confirm the amount they are adding. Offer manual entry if the product is missing or the lookup fails. |
| INV-06 | Use the same inventory form and validation for all entry methods. Let the user review, edit, and confirm each item before saving it to the household pantry. Save confirmed names in both languages when available. Keep quantity, unit, location, and expiry as shared values. |
| INV-07 | Record new stock additions alongside uses and discards. Show the member's current name and avatar, the quantity, and the timestamp in **History** and on the stock entry. Keep recorded events after stock is depleted or removed. Older stock entries have addition history only when an addition event was recorded. |
| EXP-01 | Display dated food as **Past date**, **Due today**, **Use soon** (one to three days away), or **Later**. Group entries due today and in the next three days in the use-soon view, sorted by date. Food without a date appears as **No date** in inventory. |
| SET-01 | In **Settings**, let each signed-in user add or remove ingredient names under **Foods to avoid**. Only the account owner can read or edit the list. Use the list as the default for that member’s meal requests. All household members can still view and manage the full pantry. |
| SET-02 | In **Settings → Profile**, show the member's read-only username and let them edit their first and last names. Require both names on save, including for older accounts with missing names. Trim surrounding whitespace and accept 1 to 200 characters per name. Save changes to the signed-in account and update the sidebar display name. |
| REC-01 | In Settings, let household members select or deselect cooking equipment using labeled cards. Save each change to the shared household. Show previously saved custom items as selected cards and let members remove them. When a member opens Meal ideas, import their foods to avoid and the household's equipment. Allow either list to be edited or cleared for the current request. The server sends eligible household stock and the effective selections to OpenAI when configured. |
| REC-02 | Include entries with positive quantities and recorded dates of today or later, plus undated entries with positive quantities. Exclude any entry whose item name or saved English or Thai name matches an entry in the effective **Foods to avoid** list for the request. Compare names independent of the selected display language, ignoring case and leading, trailing, or repeated spaces. Combine matching quantities across eligible entries within compatible units. Count, mass, and volume are distinct. |
| REC-03 | When AI generation is enabled, show a menu with one to five dishes. Generate dish names, display names for ingredients and equipment, and ordered cooking steps in English and Thai in the same response. Share ingredient quantities, units, and equipment references across languages. Ask OpenAI to use only the supplied ingredients and equipment, including in the steps. Before displaying the recommendations, validate both languages, confirm that each listed ingredient is still eligible for the requesting user, check quantities across all dishes against current stock, and verify that the listed equipment is available for the request. Omit invalid recipes and show at most five valid ones. |
| REC-04 | If the pantry has no in-date or undated stock with positive quantities, prompt the user to add stock. If the effective **Foods to avoid** list filters out all eligible stock, explain why and let the member edit exclusions in the meal form. In either case, skip the OpenAI request. If OpenAI returns no suitable menu, show that outcome. If the request fails or returns an invalid menu, show a clear error and let the user try again. Users record ingredient usage manually through INV-03. |
| REC-05 | In V1, start with two servings, unrestricted time, and any difficulty. Allow one or more servings. Offer multiple dietary styles (vegan, halal, custom), a single optional nutrition goal (calorie control, high protein, custom), and multiple cuisines (Thai, Chinese, Japanese, Korean, Italian, custom). An empty diet or cuisine selection allows any. Offer 15, 30, 60, or 120 minutes or unlimited, and any, easy, medium, or hard difficulty. Generate returns up to five recipes with total cooking time, difficulty, ingredients, equipment, and steps. Preview the selections and stock when generation is unconfigured. |
| DATA-01 | Store household membership, shared inventory, usage and discard records, shared equipment, validated bilingual menus, and account settings in PostgreSQL. Signed-in users can access their household's shared data and their own settings and menus from another browser. Show a clear error if a change could not be saved. |
| LOC-01 | Let the user switch between English and Thai. Display UI labels and messages in the selected language. Select the stored language variant for item names and generated menus without calling OpenAI again. For manual entries and barcode results with only one name, display that name in either language. |

## Data model

| Record | Fields |
| --- | --- |
| Household | ID |
| Household membership | Household ID, account ID |
| Account | ID, username, password hash, first and last names (may be absent on older accounts), optional read-only profile picture URL, preferred language (`en` or `th`), foods to avoid (ingredient names) |
| Account session | Token digest, account ID, expiry timestamp |
| Stock entry | ID, household ID, item name, optional English and Thai names, remaining quantity, unit, location, optional expiry date |
| Cooking equipment | ID, household ID, name |
| Generated menu | ID, account ID, creation timestamp, dishes with bilingual names and steps, ingredient references with bilingual labels and shared quantities and units, and equipment references with bilingual labels |
| Inventory event | ID, stock entry ID, actor account ID, item name, change type (added, used, or discarded), quantity, unit, timestamp |

Store expiry dates as calendar dates. Determine today using the household member’s local date so due-today status changes at local midnight. Keep the first-release units to `each`, `g`, `kg`, `ml`, and `l`. Support decimal quantities for weight and volume and whole numbers for `each`.

## Usability requirements

- Show signed-out visitors a bilingual landing page with links to sign in and create an account. Opening the home page with an active session takes the member directly to household setup or inventory.
- Treat landing-page and dashboard 3D illustrations as optional decoration. Keep pantry data and actions in accessible HTML, show a static fallback if WebGL is unavailable, honor reduced motion, and stop animation while offscreen or in a hidden tab. Illustration loading must not block core tasks.
- Support phone and desktop layouts. Give all form controls visible labels, support keyboard navigation, and convey expiry status with text.
- Show clear empty states for inventory and food due soon. Show a loading state during menu generation and give the user a next action when a menu is unavailable.
- Keep manual entry available when the camera is unavailable or permission is declined. Show progress for photo analysis and barcode lookup and keep the entry editable while reviewing results.
- Validate quantities and dates before saving. Reflect failed saves in the interface and preserve the user's form input for retry.
